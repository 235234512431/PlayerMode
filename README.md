# PlayerMode 0.6.1

给 SillyTavern 套上极简玩家界面，保留原生聊天、角色、世界书、Preset、正则、生成和保存流程。

## 0.6.1：主题窗口与新对话修复

- 主题窗口固定显示“取消”和“应用外观”，选项与阅读设置在中间单独滚动，避免手机或短屏找不到按钮；右上角新增关闭按钮。
- 取消、右上角关闭或 Escape 会恢复之前的主题、字号和行距；应用后按当前浏览器和账户记住组合。
- 新对话等待原生确认结果，取消后保留书架；确认期间阻止重复新建，并复核角色和当前对话没有发生变化。明确保留原对话，不提供删除历史选项。
- 切换前调用原生聊天保存；对角色删除、列表变化、历史记录异常及原生操作未完成增加检查和错误提示。

已完成针对性隔离测试与桌面、390×600 短屏浏览器检查。真实酒馆端到端流程的未验证项见文末与 [VERIFICATION.md](VERIFICATION.md)。

## 0.6.0：故事书房与扶沟高中专供界面

- 书架采用书封与书脊的排版，加入雨窗、台灯和翻开的书的轻量 SVG 线描。图形只放在入口，保持聊天正文易读。
- 角色封面提供真正可用的书签收藏；“我的收藏”按本浏览器、原生账户分开记忆。搜索只筛选已开放角色，不读取其他账户内容；可一键清除。
- 已有当前角色时，可直接“回到当前对话”；未选择角色时显示默认故事入口。角色历史采用书签式列表，继续使用原生打开与新建流程。
- 新增 **扶沟高中 · 窗世界** 专供主题：教室窗格、课桌与练习本线描、校园档案标签、黑板绿与纸页金，以及专属书架标题。主题只改变展示，不改变世界书或角色卡。
- 专供版暂以校园黄昏作为视觉底稿；尚未获得具体世界观片段，没有加入虚构校史、人物关系、剧情或校徽。

在顶部“切换主题”选择 **扶沟高中 · 窗世界**，点击“应用外观”即可。仍可切回其他三种风格，也可组合字号与行距。

0.6.0 发布时按用户要求未运行验证；0.6.1 已补做上述针对性检查。没有修改本机 SillyTavern 安装或启动服务器。

## 0.5.0 主题切换

顶部“切换主题”提供“雾紫夜谈”“雨夜书房”和浅色“旧信笺”三种预设：青灰底、纸色正文、暖金强调和书脊细节。选择可即时预览，取消或 Escape 恢复原主题；可调节 14–22 px 正文字号与 1.60–2.20 倍行距，并查看示例；点击“应用外观”记住组合。外观偏好仅保存在当前浏览器，按原生账户区分，不修改共享密码、角色、世界书或聊天。浏览器禁止存储时仍可在当前页面使用，并提示无法记住。

按用户要求停止后续验证：早期两主题偏好版本的隔离测试通过；最终三主题及阅读调节版本按要求未运行验证，也未做浏览器视觉验收。

## 安装与更新

在 SillyTavern → 扩展 → 安装扩展填写：

```text
https://github.com/235234512431/PlayerMode
```

已安装时使用扩展管理中的更新按钮，再刷新页面。检查版本为 **0.6.1**。不要重复安装。如果仍是旧版，先确认扩展管理显示的提交和版本；本地 Git 检查更新不等于已将远程提交合并到工作目录。

手动安装可把整个目录复制到 `SillyTavern/public/scripts/extensions/third-party/PlayerMode/`，或实际数据目录的 `<用户标识>/extensions/PlayerMode/`。不重复安装，不覆盖其他目录。manifest 位于扩展根目录。无需构建、无需框架依赖。

## 更新到 0.4.0：先准备角色，再邀请朋友

0.3.0 的共享退出密码继续有效。新增角色范围默认为空，升级后可能看到空书架，这是等待站主配置，不会自动开放全部角色或回退默认助手。

1. 每个朋友使用不同的 **SillyTavern 原生账户**。账户开通方式见下一节。
2. 由你先登录各账户，准备角色卡、角色绑定的世界书、模型连接、Preset 等。
3. 初次使用，在扩展设置中设置至少 8 个字符的统一退出密码；已有密码则先用它退出玩家模式。
4. 打开 **PlayerMode → 开放角色与默认角色**，输入该账户退出密码。
5. 选择“开放本账户全部角色”（以后新增角色也开放），或取消此项后逐一勾选角色；必须指定一个开放的默认角色。
6. 等待“角色范围已保存”，点击“进入玩家模式”或刷新，再邀请朋友登录。

同一个原生账户的不同浏览器共享退出密码和开放角色配置。不同原生账户分别配置；若你希望所有朋友使用同一个退出密码，可由你在各账户分别设置相同值。扩展不会跨账户复制密码或数据。

## 原生独立账户：由站主手动配置

1. 根据 [SillyTavern 官方多用户说明](https://docs.sillytavern.app/administration/multi-user/)，在服务器 `config.yaml` 确认 `enableUserAccounts: true`，若有修改由你重启服务器。
2. 用原生管理员账户进入用户设置的账户管理，为朋友创建普通账户，并配置各自的登录密码。扩展设置也提供“原生账户管理”入口，仍由酒馆检查管理员身份。
3. 确认每个账户都能加载 PlayerMode；当前账户私有安装不会自动分发给其他账户，可按原生扩展管理提供的全用户安装方式部署，避免重复安装同一扩展。
4. 分别登录朋友账户，导入你允许的角色卡和世界书，配置模型、Preset 以及 PlayerMode 密码和默认角色。新账户不会自动继承你原账户的这些内容；无需复制私人历史聊天。
5. 用两个独立浏览器登录不同账户，分别发送一条测试消息，确认双方历史列表彼此独立，再正式使用。

“切换账户”会先调用原生聊天保存，再调用原生退出登录，返回酒馆登录页。登录密码、会话认证、用户目录和聊天隔离全部由 SillyTavern 管理；扩展不创建另一套账号系统。若仍共用同一登录账户，对话就仍会共享。原生账户管理不是隔离的沙箱，具体安全边界以官方说明为准。

0.2.0 的本地密码不会自动迁移，也不再用于验证。共享配置成功保存后，只清除当前浏览器旧的 `PlayerMode.preferences.v1` 键。

密码保存在 SillyTavern 原生账户设置的 `extension_settings.PlayerMode` 中，密码部分仅含随机盐和 PBKDF2-SHA-256 校验值（210000 次迭代）；不保存明文密码、不发往模型、不提交到 GitHub。不要使用重要账号密码。

不同 SillyTavern 账户仍有不同配置；这不是跨账户的全站密码。首次尚未设置时保持普通界面，由站主先配置，不能先开放给朋友再期待系统区分站主。

## 退出、修改与恢复

- 玩家界面提供角色标题、对话书架、新对话、切换账户、退出玩家模式，以及账户和连接状态；聊天输入与发送使用原生节点。
- 点击“退出玩家模式”或按 `Ctrl+Shift+P`，使用共享密码验证。验证时读取服务器最新配置，断网或读取失败不会退出。
- 解锁只影响当前页面，不保存 OFF。**刷新重新进入玩家模式**，其他浏览器不受本次退出影响。
- 返回普通界面后可在扩展设置修改密码，必须验证当前共享密码。保存后重新进入玩家模式。
- 密码保存通过原生设置机制执行，并回读服务器核对后才提示成功；失败保留字段，可以重试。超时存在原生请求稍后成功的可能，请刷新确认实际状态。
- `?playermode=0` 不提供免密码恢复。

忘记密码时先禁用扩展并刷新。无法进入扩展管理时，可把 PlayerMode 安装目录移出扩展扫描位置再刷新。需要彻底重置共享密码时，在扩展禁用期间，由站主在该站点开发者工具控制台执行下面两行，再等待原生保存完成：

```js
const playerModeContext = SillyTavern.getContext();
delete playerModeContext.extensionSettings.PlayerMode;
playerModeContext.saveSettingsDebounced();
```

这只删除 PlayerMode 自己的账户配置。重新启用扩展后刷新，重新设置密码。不要清空整个站点存储或删除整个 settings 文件。

## 深色阅读界面

深蓝灰底与雾紫强调、宋体角色标题、约 860px 阅读区；保留头像和原生富文本，用户消息用轻底色区分。桌面及手机响应式布局，保留滚动条和原生输入框自适应逻辑。

密码窗口具备可见标签、显示／隐藏密码、行内错误、焦点约束、取消、Escape、忙碌状态和键盘操作。CSS 仅在玩家模式时覆盖宿主；关闭后恢复原生样式，扩展自己的设置控件仍可见。

## 书架、历史与新对话

- 顶部“对话书架”始终提供返回角色列表的入口，点击角色查看该角色的历史，再打开已有对话或“为此角色新建对话”。历史加载支持空列表、错误重试和加载更多。
- 书架上的顶部“新对话”使用配置的默认角色；聊天中的顶部“新对话”使用当前开放角色。
- 先通过原生选择角色流程切换并核对角色，再触发原生新聊天确认。角色已删除、未开放、切换失败时提示错误，绝不降级为默认助手。
- 世界书按你在原生界面为目标角色及账户配置的绑定生效。扩展不拼接提示词，不自动绑定或复制世界书。
- 模型生成中禁止打开书架、切换对话和账户；输入框有草稿时禁止切换/新建，提示先发送或清空。不会默默丢弃草稿。
- 打开书架只隐藏原生聊天，不重建消息节点。新对话使用原生弹窗确认，确认后调用原生新建函数并明确保留当前聊天；取消不新建，也不关闭书架。原生保存接口可能自行处理错误，扩展不额外承诺服务器保存事务成功。
- 目前书架仅支持单角色对话，不列出群组。进入玩家模式时若当前是群组或不开放的角色，会显示书架。

## 边界与已知限制

- 这是统一的 **UI 退出密码，不是服务器权限系统**。同账户访客可用开发者工具、设置接口或禁用扩展绕过。首次加载到 APP_READY 前可能短暂显示普通界面。
- 真正独立聊天要求不同原生登录账户。角色开放范围及退出密码仍是 UI 约束，不能代替服务器权限。
- SillyTavern 保存完整账户设置，旧页面同时保存可能覆盖新配置。本扩展不会补丁式接管宿主保存流程。修改密码或角色范围后，刷新该账户其他已打开的页面；避免多人同时修改设置。读回验证不等于服务器字段级事务。
- Web Crypto 需要 HTTPS 或 localhost；普通远程 HTTP 无法验证密码。
- 主题、第三方浮窗和未来 DOM 改版可能影响显示。未整体隐藏通用弹窗，以保留原生交互。
- 配置损坏、未配置或关键 DOM 缺失会保持普通界面并提示；它不是安全边界。
- 未接管原生自动滚动、输入快捷键、流式生成、模型请求或世界书扫描。

## 禁用与卸载

禁用/删除独立扩展后刷新即可恢复普通 UI。不删除聊天、角色卡、世界书或 API 配置。共享密码设置不会因删除目录自动清除，需要彻底重置时使用上面的专用键清理步骤。已加载的 JS/CSS 需要刷新才会消失。

## 开发依据与验证

只读调查本机 SillyTavern **1.18.0**：`extensions.js` 的 manifest 加载、`st-context.js` 的上下文、`events.js` 的 APP_READY/SETTINGS_UPDATED、`script.js` 的原生新聊天和设置保存，以及 `/api/settings/get` 的设置响应。无宿主文件修改。

运行隔离测试（需支持 Web Crypto 的现代 Node.js）：

```text

```
